# 2–3 分钟演示脚本

## 录制前准备

1. 后端和前端均已启动，浏览器缩放为 100%。
2. 使用事实完整、不触发追问的脱敏样例：“合同约定收到货款后 7 日内交货，现已过去 30 日仍未交货，我要求解除合同并赔偿。请结合合同法第九十四条和民法典第五百六十三条分析。”
3. 先选择 `2020-12-31` 生成历史时点结果；可再用 `2021-01-01` 快速对比现行版本。
4. 准备一个离线审批结果；可选准备一个成功的 Agent 运行结果。
5. 关闭包含 API Key、PyCharm 环境变量和私人通知的窗口。

## 分镜与讲解

### 0:00–0:20 项目问题

展示首页并说明：直接让模型回答法律问题可能虚构法条。本项目将案件抽取、法规检索、引用审核和报告生成拆成可追踪节点，所有引用都能回查数据库 ID。

### 0:20–0:50 提交案件

粘贴脱敏问题，选择案件发生日期 `2020-12-31`，切换“智能 Agent”或保持离线模式，点击分析。指出接口立即返回任务 ID，日期与任务一起持久化，长任务在后台执行。

### 0:50–1:15 查看轨迹

展示节点、耗时、执行引擎和“法规适用时点”。说明检索不是先取 Top-K 再剔除废止法，而是在召回前按日期区间过滤，避免无效版本占用候选。

### 1:15–1:45 草稿、引用与审批

展示“待审批草稿 V1”和引用抽屉。指出《合同法》第九十四条显示“1999年施行版本”“已废止·历史时点适用”，并展示 `law_version_id` 与 1999-10-01 至 2021-01-01 的区间。说明历史时点可引用不等于它现在仍有效。

### 1:45–2:10 版本差异与批准发布

批准当前草稿并展示最终下载。若时间允许，点击“分析新案件”，改为 `2021-01-01` 提交同一问题，展示结果切换为现行《民法典》第五百六十三条；这证明版本差异来自日期过滤，不是随机模型输出。

### 2:10–2:30 运行监控

点击执行区的 Trace 链接，展示“运行监控”页面。指出同一个 Trace ID 能关联创建请求与 Agent 链路，页面可直接回答最慢节点、实际模型、Token、估算费用、重试与降级原因；离线模式显示 0 Token/费用是诚实结果。强调 Span 使用属性白名单，不保存案件全文、Prompt 或密钥。

### 2:30–2:43 评测

展示 `eval/results/latest.md`：24 条脱敏数据、案件类型准确率、Recall@5、MRR、工作流成功率。主动说明当前小数据集上关键词优于哈希向量，真实 Embedding 组尚需独立服务。

### 2:43–2:53 工程质量

展示 GitHub Actions：Ruff、mypy、82 项测试、离线评测和前端构建。说明第八周 7 项测试覆盖 Trace 关联、节点 Span、聚合指标、Token/费用、隐私白名单和旧任务兼容。

### 2:53–3:00 收尾

展示架构图和限制：版本演示数据不等于官方自动更新法规库；后台任务尚未迁移持久队列；当前监控保存在本地 SQLite，生产环境仍需要 OTLP/告警、PostgreSQL/pgvector、RBAC 和同步审计。
